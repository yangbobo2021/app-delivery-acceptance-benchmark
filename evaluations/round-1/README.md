# 第一轮交付验收 SKILL 能力验证

基线是公开仓库 `main` 的四个独立小项目；本测试分支冻结于 `61b529a7b810c3dd2cc2bdbca5cf286806e78571`。项目原始 `docs/requirements.md` 是行为依据。测试分支新增的 `tests/`、`.acceptance/` 和本目录均为本轮产物，`main` 仍保持清洁基线。

执行顺序是：**先让每个项目各自跑通一条完整 v4 流程**（含项目准备、单场景编写、真实执行、覆盖率、独立审查与归档）；随后为四个项目的全部 24 条需求生成并审查场景列表；最后在每个项目再执行一条不含预置缺陷的场景。因此每个项目实际执行了两条不同场景，其他生成场景没有执行。

| 项目 | 场景数 | 已执行 | 预置缺陷场景 | 非预置场景 | 最终判定 |

四个预置 BUG 都有生成场景覆盖，并被正式执行和独立审查识别。四条非预置场景最终通过；本轮没有确认额外产品 BUG，也没有最终误报。**这只是每项目两条场景的抽样结论，不代表其余 83 条场景或四个项目已完成需求验收。** 每个项目的结果视图都显示完整场景分母、已执行 2、通过 1、产品 BUG 1，且无统计告警。

本轮同时检查中间产物。Python 首次正式尝试遇到共享 Git 目录覆盖率策略互相覆盖；Go 首次覆盖率只收集父进程而得到 0%，下一次原始子进程数据又未冻结；Go 非预置场景的覆盖率适配器曾写死预置场景名。Electron 在 Agent 环境的本地启动失败、宿主首次执行有页面导航竞态和证据路径问题。Web、Go 与 Electron 的独立审查还分别退回过无依据的测试断言或测试清理代码。以上均定位为**测试流程／夹具问题**，已修正、重新冻结并复审；原异常没有改写为产品缺陷。最终归档在各项目 `.acceptance/<ID>/records/`；首次异常的关键冻结请求、日志、判断和退休凭据在 `checkpoints/`，完整原始尝试仍保存在各项目被忽略的 `.acceptance-local/` 目录。

场景列表的逐项目审查见 [scenario-audit.md](scenario-audit.md)。审查发现重要度划分、需求归属和可观测断言方面的具体问题，因此不能声称当前生成器的场景质量已经完全达标；本轮按照约定**记录问题而未直接改写冻结场景或优化生成工作流**。各列表的来源与哈希见 `scenario-sources-*.json`。

覆盖率按项目自行准备并以原生工具采集：Python 使用 `coverage.py` 行／分支，Go 使用 Go 原生进程 `covdata` 语句覆盖率，浏览器项目使用 V8/c8，Electron 使用 V8/c8。Go 原生工具未提供经核实的行／分支数，因此如实显示不可用；Electron 的主进程、存储与构建部分尚无可信完整指标，因此整个项目覆盖率显示为不完整。覆盖率只对应实际执行的两条场景，不外推到其余场景。
